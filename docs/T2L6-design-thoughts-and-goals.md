# T2L6 设计思路与目标

## 1. 适合的学习方式

- 本设计面向的学习方式，不是“从零搭完整工程”，而是“先理解整体框架，再聚焦关键实现点”。
- 这种方式更适合操作系统课程中偏系统实现的内容，原因在于：
  - 章节框架、运行路径、测例组织、构建流程如果全部由学生自行搭建，容易分散注意力。
  - 相比之下，先提供完整脚手架，再让学生补少数核心逻辑，更有利于把精力集中在原理和实现关系上。
- 对虚拟内存算法这一主题而言，这种学习方式尤其合适，因为：
  - 需要先看到缺页异常、页表状态、用户态访存模式、统计输出之间的整体关系；
  - 在此基础上，再去实现某几个核心算法点，学习效果会更直接。

## 2. 设计背景

- `tg-rcore-tutorial` 前八章已经完成了从裸机启动到线程与同步原语的整体教学路线。
- 其中 `ch4` 已经引入了地址空间、页表、页权限、`mmap`、`sbrk` 等与虚拟内存密切相关的基础机制。
- 但是从“能建立页表映射”到“能处理缺页、支持换页、观察局部性与抖动”之间，仍然存在一个明显的教学空档。
- 因此，T2L6 的基本出发点是：
  - 在现有教程体系中增加一章新的虚拟内存算法章节；
  - 把原本偏概念性的分页算法内容，变成可运行、可测试、可比较的教学实验。

## 3. 设计目标

- 目标一：新增一章与原仓库风格一致的教程章节，用于讲解虚拟内存算法。
- 目标二：让章节主题聚焦在以下几个真正值得学习的点上：
  - 匿名页懒分配
  - 缺页异常处理
  - 页面置换
  - 工作集与抖动现象
- 目标三：章节形式保持与 `ch1~ch8` 一致，具体包括：
  - 独立章节目录
  - `README.md`
  - `exercise.md`
  - `test.sh`
  - 用户态测例
  - 少量明确的 `TODO` 挖空点
- 目标四：避免将本章变成“完整参考答案”或“纯工程搭建题”，而是保留教程应有的练习属性。

## 4. 初步设想

- 初步设想是直接补出一个完整可运行的 `ch9`，一次性实现：
  - FIFO
  - Clock
  - LRU-approx
  - Working Set
  - Thrashing 检测
- 这一设想的优点在于结果完整、展示效果直接。
- 但进一步分析后发现，这种做法更接近参考实现，而不太像教程：
  - 学生面对完整答案时，容易停留在“阅读和运行”的层面；
  - 真正需要自己思考和实现的部分反而不清楚。
- 因此，后续设计方向调整为：
  - 保留完整脚手架；
  - 保留统一的用户态测例与统计输出；
  - 只挖出最有教学价值的核心实现点。

## 5. 总体设计思路

- 整体基底选择：
  - 本章基于 `ch4` 继续递进，而不是直接挂在 `ch8` 之后。
  - 这样做的原因是 `ch4` 已经具备地址空间和页表基础，但整体复杂度仍然较低，更适合讲清分页算法主线。
- 章节定位选择：
  - 本章应是“教程章”，不是“补丁合集”。
  - 因此需要有完整章节边界，而不是只在现有某章中临时塞入一组额外函数。
- 教学重心选择：
  - 本章重点应放在“缺页、换页、算法比较”。
  - 不应把主要工作量放在 syscall 定义、日志协议、build 流程、测例拼装等外围事项上。

## 6. 章节规划

### 6.1 基础部分

- 基础部分建议作为本章的最小通过要求。
- 学生需要完成的内容包括：
  - `mmap/sbrk` 的懒分配登记
  - 合法缺页异常恢复
  - FIFO 页面置换
  - Clock 页面置换
- 这一部分完成后，可以形成一条完整闭环：
  - 先登记虚拟页；
  - 首次访问触发缺页；
  - 分配物理页或换入页面；
  - 常驻页满时按算法选择 victim；
  - 后续再次访问时继续恢复。

### 6.2 扩展部分

- 扩展部分建议作为进阶任务，不强制纳入最小通过要求。
- 扩展内容包括：
  - LRU 近似
  - Working Set
  - 抖动检测与动态调参
- 这样的分层有两个好处：
  - 基础部分已经足够形成完整教学主线；
  - 扩展部分可以给能力较强或时间较充足的同学继续深入。

## 7. 具体实现设想

- 章节目录层面：
  - 新增 `tg-rcore-tutorial-ch9/`
  - 提供完整的 `README.md`、`exercise.md`、`build.rs`、`test.sh`
- 内核层面：
  - 保留现成的启动流程、trap 分发、syscall 注册、用户态装载流程；
  - 只在与分页算法直接相关的位置留空。
- 用户态层面：
  - 直接提供 benchmark 程序和固定访存 pattern；
  - 不要求学生自行设计测试协议。
- 公共接口层面：
  - syscall 编号、统计结构体、用户态 wrapper 等建议直接给好；
  - 避免学生把时间耗在与本章主旨无关的接口拼接上。

## 8. 建议挖空的位置

- `src/process.rs`
  - `change_program_brk`
  - `mmap_anonymous`
  - `handle_page_fault`
- `src/pager.rs`
  - 缺页主路径
  - FIFO victim 选择
  - Clock victim 选择
- 对于扩展题，再继续挖空：
  - LRU-approx
  - Working Set
  - Thrashing 检测

## 9. 不建议挖空的部分

- 不建议让学生自己补：
  - `build.rs`
  - 章节目录和 README 主体结构
  - userland benchmark 组织
  - syscall 常量和用户态 wrapper
  - checker 或输出协议
- 原因是这些部分虽然也属于实现工作，但对本章的主要教学目标帮助有限。
- 如果这些外围部分也全部交给学生实现，会削弱本章“虚拟内存算法”这一主线。

## 10. 预期效果

- 如果本设计按预期实施，完成后的章节应达到以下效果：
  - 学生进入本章后，能快速理解章节边界和实现重点。
  - 学生完成基础部分后，能够看到缺页和置换确实在运行，而不只是停留在概念层面。
  - 学生运行 benchmark 时，能够观察到不同算法在不同局部性模式下的差异。
  - 整章风格与 `ch1~ch8` 保持一致，不会显得像仓库外的独立实验。

## 11. 小结

- T2L6 的核心设计思路，不是追求“功能尽可能多”，而是追求“学习路径尽可能清楚”。
- 本设计认为，对于虚拟内存算法这一主题，更合理的形式是：
  - 保留完整脚手架；
  - 固定测试与输出协议；
  - 把少数最有教学价值的实现点留给学生完成。
- 从教程角度看，这种形式比直接提供完整答案更有练习意义，也比完全空白工程更适合作为课程实验。
